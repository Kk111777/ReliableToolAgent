# 测量复核：另一模型会话

[English](README.md) | **简体中文** · [返回项目](../../README.zh-CN.md)

另一个 Codex 会话核对了 20 个有目的选择的片段：12 个来自历史开发面板，8 个来自冻结主实验的保留首次尝试。对方收到填写说明、片段与空表，在与分析器作者预标签对照前，保存了首份结果。

## 首份判断与对照

| 范围 | 与既有协议标签的一致程度 |
|---|---|
| 全部 20 个片段，每条六字段 | **117/120** |
| 参考动作可用的 17 个片段 | **102/102** |
| B08、S02、S06 | 各有一处分歧：成功参考匹配数填了 `0`；原协议使用 `null`。 |

[精简记录](summary.json)同时保留首次标签与协议标签，包含参考可用性、不确定标记、对照计数及来源指纹，不包含原始消息或业务参数。

三条片段都缺少参考信息，且没有观察到 WRITE 调用窗口。对方据此填写成功匹配数为 0，并标记不确定；原说明没有明确交代这个计数字段的可用性要求。原协议统计的是“参考匹配数”，前提是参考信息可用，因此即使观察到的调用列表为空也保留 `null`。参考信息可用且明确为空列表时，才填 `0`。

这条说明在收到首次结果后补充。首次判断、原 reviewer 压缩包、预标签及旧实验分数都保持原样，没有用裁定结果替换首份标签，也不宣称对方后来认可了补充规则。

## 核查范围

接收方已核对保存的 JSON 与会话首次最终回复一致，按保留的来源哈希重新关联 20 个片段，并从调用／响应窗口和终止标记复算六个协议字段。下面的公开入口检查精简记录的 schema、payload 哈希和逐行计数，不能认证未公开的原始证据或复核者上下文。

```bash
.venv/bin/python scripts/audit_model_review.py \
  --input reports/model-review-v1/summary.json
```

对方自报未看隐藏答案或分析器结果，但披露会话自动带有项目概况，具体模型版本未知。因此记录为另一会话的模型复核，不称严格独立盲审、独立人工标注或不同模型之间的验证。选定片段不是随机准确率样本，标签一致程度不等于测量准确率。

对方也指出字面 STOP 标记与继续操作请求同时出现，以及成功换货不匹配退货参考。这些属于诊断观察，不能由此判断官方任务失败、数据库状态或组件因果。[测量定义与边界](../../docs/engineering_v2.zh-CN.md#测量-v2把部分完成保留下来)。
