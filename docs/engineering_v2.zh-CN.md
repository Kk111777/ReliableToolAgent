# 工程修补 v2

[English](engineering_v2.md) | [返回项目](../README.zh-CN.md)

这轮修补处理三个可复现的问题：state 引用改变后 Guard 误拦截、模型响应格式导致的评测中断，以及部分 WRITE 已完成时的终止指标漏检。旧研究的 210 个首次尝试、评分、93/105 有效配对和工程门槛未通过结论保持原样。

## Guard：按执行目标判断重复

原先模型两次发送 `{"order_id":"lookup"}`，即使 `state["lookup"]` 从不存在的订单改为有效订单，也会命中第一次的失败历史。现在每次调用只解析一次 state 引用，Guard、实际执行与失败记录使用同一份有效参数。

逐调用记录保留原始 `arguments`，另存 `resolved_arguments`；`normalized_arguments` 表示执行目标。两个不同引用指向同一目标时仍能匹配；引用改变为新目标时允许执行。别名链仍只解析一层，避免无意改变已有语义。

这解决的是调用参数身份。相同参数下外部数据库状态变化、并发请求尚未记录失败时的重复执行，仍需业务失效策略或幂等接口；Guard 不承诺解决这些问题。

公共 `execute_tool_call` 的普通观测 hook 可继续转调 `super`。若 hook 在 Guard 检查后改写工具名或参数，会在执行前明确拒绝，避免检查与实际执行分离。执行对象保持原有身份，日志保存调用前的 JSON 快照；不支持绕过基类自行执行的 override。

## 响应适配：有限恢复，保留失败

新入口 [`engineering_worker.py`](../benchmark/tau3/scripts/engineering_worker.py) 在独立进程中组合原 worker，退出时恢复适配器。没有修改冻结的 `study_worker.py`、Agent 提示、模型、输出上限或评分器。

- **空 User 响应**：文本为空且没有工具调用时，使用相同输入最多再生成一次。两次调用均计费并记录；仍为空则抛出明确错误，不补写用户话语。连接错误、预算停止和取消直接传播。
- **evaluator JSON**：只移除完整包裹回答的一层 `json` 或无语言 Markdown 围栏。必须严格符合官方字段、布尔类型和预期断言的数量与文字。拒绝夹带说明、损坏 JSON、重复键、空结果、字符串布尔值；不会修改判定值。最多两次格式重试，所有响应指纹和调用序号留存。
- **安全诊断**：保留固定阶段、白名单异常类型、可信源码相对位置和原因类型。不会序列化异常消息、变量、请求头或完整响应。外部源码位置脱敏。源码位置能定位新故障，不会追认旧九个 ValueError 的完整因果。

这些是新协议下的恢复规则。额外请求会改变费用和生成过程，不能把新运行混入旧首次尝试。

## 测量 v2：把“部分完成”保留下来

[`measurement_v2.py`](../benchmark/tau3/scripts/measurement_v2.py) 是独立诊断入口。每个成功工具响应最多匹配一个参考 WRITE，按出现次数计数；未知结果不视为成功。终止时仍有未匹配的参考 WRITE 即为候选，因此能够覆盖“完成前几步，但漏掉最后一步”。

没有实际 STOP/TRANSFER User 消息时，`agent_after_terminal_user_v2` 为不可用。缺少参考动作或轨迹时也保留未知，不推断成功或失败。特别地，参考信息缺失时，成功的“参考匹配数”保留 `null`，即使没有观察到 WRITE；参考信息可用且明确为空列表时，才计为 `0`。

在旧 197 条有效轨迹上，新规则标记 61 个候选，v1 为 48 个；增加的 13 个均为部分完成。案例 C03 为 2/3、C07 为 3/4。这是回顾性指标覆盖修正，不是新增成功、因果解释或性能提升。相同业务效果可能通过不同参数实现，精确参考匹配不能替代官方评分。

## 验证与证据边界

离线测试覆盖 state 别名、重复身份、单次解析、空输出重试、取消、格式与 schema 拒绝、诊断脱敏、WRITE 重数和未知值。旧两次 evaluator 故障的六个保留围栏响应已逐条离线回放，全部严格通过，布尔值与内容不变；没有重新评分旧尝试。

另用已暴露的开发任务 0、5，各 U0/U2 一次，建立四槽工程接通检查。固定原模型参数、600 秒限制、逐 HTTP 预算及历史费用基线；不补跑，不按 reward 筛选，不自动扩展。结果见[工程证据](../reports/engineering-v2/README.zh-CN.md)。这是接口 smoke，不能测定故障率下降，也不是新 holdout。

历史标注、案例和新测量核对都来自同一作者及代码审查，没有独立人工验证。后续[另一会话模型复核](../reports/model-review-v1/README.zh-CN.md)检查了 20 个选定片段，保留了首份结果的三处计数分歧，并暴露出上文补清的可用性规则歧义。对方披露自动项目背景，这次复核不属于严格独立盲审。公开精简数据可以检查行身份、来源哈希及汇总一致性；重新判断原始语义需要本地轨迹。

共享的可变 state 对象仍保留执行身份。执行前会复核其内容，发现 hook 就地改写则拒绝；调用期间其他线程修改同一对象不具备隔离保证，需要外部同步。
